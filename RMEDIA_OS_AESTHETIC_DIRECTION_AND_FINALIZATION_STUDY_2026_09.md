## 2. Executive summary
The ecosystem is **structurally more mature than it looks**. The product has a real point of view (a kitchen-display "pass": comandas, LET'S COOK, War Room as a KDS for a solo editing bay), a trustworthy evidence language (SOURCE FACT / DERIVED chips, mono system labels, breadcrumb strip "CLIENT → PROJECT → VIDEO → WORK → REVIEW → RESULT"), and calm, well-built client entry points. What undermines it is **visual dialect drift**: the public site is a Tibia-style pixel-game UI (red/green/gold neon, Press Start 2P, "Lobby / Player HUD / XP bar / class cards"), the product is a violet-on-zinc modern dark app, and the operator layer adds saturated solid tiles, 140 emoji icons, pixel corner-brackets and ambient "lamp flicker" — three different dialects behind one brand.
**Verdict: aesthetic maturity is roughly "prototype with excellent bones."** Client-facing product surfaces are near finalization; the public site is content-ready but costume-mismatched for the target clients (coaches, mentors, educators); the operator UI is dense and useful but visually noisy.

## 3. Ecosystem-wide diagnosis
**Coherent already (keep):** dark neutral base everywhere; Inter as the body face on public, intake, login and client surfaces; mono uppercase micro-labels for system state; hairline-bordered panels; consistent Sensor/Session semantics; the intake form and both login cards share one layout; status pills follow one grammar (uppercase, small, tinted); mobile bottom nav exists; custom keyframes are guarded by `prefers-reduced-motion`.
**Inconsistent:**
- **Four brand marks:** pixel-font red "RMEDIA" (public), violet "M" (client login), violet "RM" tile (intake, Vault), violet "MB" (operator/login). None is the official one.
- **Two brand primaries and three palettes:** public = #050505 + pure red #FF0000 + terminal green #00FF41 + gold + diamond; product = zinc-950 + violet + cyan + emerald + amber + red.
- **Names:** "The Vault" (token page) vs "Client Portal" (login/dashboard) vs "Client Login" (public nav); "MindBunker" (operator) vs "RMEDIA OS" (the intended idea).
- **Typography by page, not by system:** LET'S COOK pages are fully monospace headings; CRM/Finance are sans; Sessions uses Press Start 2P for day labels; the public site uses Press Start 2P for buttons/eyebrows/HUD.
- **Icons:** emoji (140 uses; sidebar, tiles, headers) plus a separate 16-glyph pixel SVG set (`PixelIcon`, 16 call sites) plus the public site's raster sprites — three icon systems.
**Immature:** operator Dashboard (five solid saturated action tiles + a multicolor "quick action" strip that includes Coffee/Bike Ride/Walk beside Add Income), War Room restaurant floor (warm lamp flicker, sim-game feel), Productivity KPI tiles (five hues + emoji), the blank white 404 on the public site, the default unbranded Next 404 on the app.
**Actively hurting trust with real prospects:** the pixel-art "Recent Work" slot (illustration stands in for real work), the gamer vocabulary ("Lobby", "Player HUD", RPG class cards, "rare loot" palette), and the hand-off seam: clicking Book a Call jumps from red pixel-game chrome to a clean violet form on a different visual system, at the URL `/mindbunker/quoteavideo` (the internal product name shows in a prospect's address bar).
**Already pointing at RMEDIA OS:** the KDS metaphor and comanda language; provenance chips; breadcrumb strip; the Production Order page (hairline panels, mono labels, honest "Not recorded" states); Production Context / Before-you-export blocks; the login cards.

## 5. Typography direction
**Diagnosis.** Usage counts: operator 426 arbitrary `text-[Npx]` uses with **10 px = 272** (too small for uppercase, letter-spaced labels), weights `font-black` 369 / `font-bold` 553 / `font-semibold` 211 / `font-medium` 83 — heavy weights dominate, which reads loud and poster-like, not calm. Body family is the system stack on the app and Inter on public/Sessions; mono is `ui-monospace` (renders as different fonts per device). Press Start 2P is the strongest "game" signal and appears on the public site and the Sessions timeline.
**Proposal (two families + one mono):**
- **UI and headlines: Inter (self-hosted variable)**, already present on every surface except the app shell. Headlines semibold (600) with slightly tighter tracking (−0.01 to −0.02 em); use Inter's display optical size for large public headings. Turn on **tabular numerals** for money, durations and timestamps everywhere (high-value for an evidence-based OS).
- **System labels/IDs/timestamps: one bundled mono** (JetBrains Mono or IBM Plex Mono, weights 400/500), used only for micro-labels, IDs, times and provenance chips.
- **Optional, public only, later:** a restrained editorial serif for a single testimonial/pull-quote moment if the brand wants warmth for expert-led clients; not required, and it should not enter the product.
- **Retire Press Start 2P** from all working and client surfaces; at most keep the pixel wordmark as a logo file (see §6).
**Hierarchy, as few sizes as possible:** 11 (mono label, caps) · 12 (meta) · 13–14 (dense UI body) · 15–16 (comfortable body) · 18–20 (section) · 24–30 (page title) · 40–64 fluid (public display). **Weights: 400, 500, 600 only** (cap the 900 usage). **Density modes:** operator dense (13–14 px base, labels never below 11 px), client comfortable (16 px), public spacious. Signals of "premium, trustworthy, utilitarian" come from restraint here, not from a decorative face.

## 6. Color / brand direction
**Diagnosis.** Operator palette share: zinc 64%, violet 9%, cyan 9%, red 6%, emerald 6%, amber 5%, plus indigo/blue/fuchsia ~2% — **five near-equal accents**. Client: zinc 56%, violet 14%, emerald 12%, amber 10%. Intake: violet 15%. Public: red/green/gold/cyan neon. Colors are doing three jobs at once: brand (violet CTA), state (emerald/amber/red), and decoration (dashboard tile hues); cyan and violet each play several roles. Pure #FF0000 and #00FF41 read as arcade/terminal toys, not premium.
**Recommended direction: neutral shell, one brand accent, four semantic colors.**
- **Neutrals (the "instrument" shell):** one warm-neutral dark ramp shared by all three surfaces (public #050505 vs app #09090b is currently a needless difference); hairline borders at ~8–12% white; off-white text, two secondary greys. Professional video tools (Resolve, Frame.io) keep the UI neutral so *the imagery carries color* — apply that principle: real thumbnails and frames are the colorful thing on public and client pages.
- **One brand accent:** the pragmatic choice is the **violet already deployed on the intake, both logins, the client portal and the sidebar**, slightly desaturated and given three steps (default/hover/pressed) — directional starting point around #8B7CF6. This is the least-change path and the accent has no semantic collision. It risks "SaaS-violet sameness"; the mitigation is distinctiveness from structure and real work (KDS, provenance language, editorial spacing), not from a louder color. **Decision needed from you (see §11):** violet (recommended) or a red "REC/tally" accent for the public site, which would then have to be kept out of danger semantics.
- **Semantic (only):** green = live/done, amber = attention/review, red = blocked/danger, neutral-or-accent = info. **Demote/remove:** cyan as a general accent (415 operator uses; keep only for links/info or remove), indigo/blue/fuchsia (≈90 uses, no meaning), neon green/gold/diamond (public), solid multi-hue dashboard fills.
- **Per surface:** public — accent only on the primary CTA, eyebrows and focus; client — accent for actions, muted semantic pills for status; operator — accent for active nav, primary action and focus; state shown by dots/edges/text on neutral surfaces, not solid fills.
- **Technical lever:** the app uses Tailwind v4 (`@import "tailwindcss"`), so the palette can be remapped globally with `@theme` variables first (one file shifts ~5,400 utility uses across operator/client/intake), with named semantic tokens introduced gradually afterwards. The static public site can share the same tokens via a copied `variables.css`.
**Brand mark:** collapse the four marks into one. Recommended: an **"RM" monogram tile** (already the most common product mark) plus an **"RMEDIA" wordmark in Inter semibold, small caps tracking**. Option B: keep the pixel "RMEDIA" only as a logo asset and make everything around it neutral (memorable, but it ties the brand to gaming).

## 7. Motion / animation readiness
**Now:** 226 transitions and 528 hover states in the operator (colors/borders mostly — fine); custom CSS keyframes (live pulse ring, lamp flicker, editor pulse, ticket pulse, stage-enter, panel-enter) with reduced-motion guards; the public site has an idle-bobbing sprite loop and card lift; **no animation library and no Tailwind `animate-*`** — a clean, low-risk base. **The Video Workspace modal has no enter/exit motion**; lifecycle changes only have a one-off `mb-stage-enter`.
**Highest-ROI subtle motion (best first five):**
1. **One motion token set** — 120–180 ms ease-out for hover/press/focus on color, border, background only (no transforms in dense tables), one shared easing, one global `prefers-reduced-motion` guard.
2. **Modal/sheet entrance & exit** for the Video Workspace and other sheets: fade + ~8 px rise (160 ms in, 120 ms out); the single most "finished-feeling" change.
3. **State-change continuity:** cross-fade status pills and a brief (≈600 ms) row tint after a server action refresh, generalizing the existing `mb-stage-enter`.
4. **Disclosure and segmented controls:** smooth open/close on `<details>` (16 in operator) and a sliding indicator on the Sessions/Finance tab switchers.
5. **Button press feedback:** a 1–2% scale/darken on press for primary actions (19 uses exist; make it systematic), plus a quiet inline "saved" tick.
**Public:** once-only scroll reveal (opacity + 8 px), nav underline, ≤2 px hover lift; replace idle-bobbing sprites.
**Avoid:** infinite ambient animation in the operator (keep only the live-session indicator), parallax, scroll-jacking, animated numbers in tables, spinner theatre or page-transition delays, anything that slows repeated operator actions. Optional later: the View Transitions API for list → detail continuity where it costs nothing.

## 9. RMEDIA OS design-system direction
**What the theme should mean:** *a calm production pass* — the discipline of a professional kitchen or editing bay, rendered as instrumentation, not as a game. Structure carries the identity; color is scarce and means something.
**Principles:** (1) one signal at a time — color only when it carries state; (2) evidence first — provenance chips, tabular numerals, honest "Not recorded"; (3) structure over decoration — no emoji, no glow except live; (4) the KDS ticket/lane metaphor, drawn flat; (5) three density modes (operator dense / client comfortable / public spacious); (6) quiet motion that confirms, never performs.
**Tone:** precise, calm, slightly warm. **Component feel:** two radii (≈8 px controls, 12–16 px panels, full for pills — today's four radii collapse to two); hairline borders instead of nested cards; tables with tabular numerals and a quiet header; inputs and buttons one size scale across intake and operator; icons from one 1.5 px-stroke line set; modals as anchored sheets. **Visual vocabulary to keep and standardize:** mono uppercase labels, status dots, provenance chips, breadcrumb strip, ticket rails.
**External references (general knowledge, not fetched live), by use:** *typography direction* — Inter and Inter display sizes, IBM Plex Mono/JetBrains Mono; an editorial serif only as a public accent; *product-surface restraint* — professional video tools (DaVinci Resolve, Frame.io) for neutral UI with color reserved for content; restaurant Kitchen Display Systems for glanceable ticket lanes (already this product's own metaphor); *premium/system feeling* — Dieter Rams-style instrument labelling (small caps labels, no ornament); *motion language* — Apple HIG "brief and purposeful" and Material's decelerate easing. None to be copied; avoid generic SaaS gradient-and-glow sameness.
**Naming architecture (structure, not copy):** RMEDIA (studio) → one client-facing name (Vault *or* Portal, not both) → MindBunker as the internal operator codename.
