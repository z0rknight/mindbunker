# Sep 18 Afternoon — Heavy Real-Work QA

This is not a test script. Just work normally — this is here so friction gets noticed, not manufactured.

## A. Start of session

- Sensor connected? War Room shows the right context before you start.

## B. Real client production

- Open the real client/project you're actually working on today.
- Open or compose the real Production Order for it.
- Open a deliverable, start work, stop work — notice if anything makes you stop and think instead of just working.

## C. Batch flow

- If today's batch includes videos you already registered earlier: select them on the Project page and **Add to batch** instead of re-creating them.
- If you're starting a new batch from a project with no open order yet: use the **Start one with LET'S COOK →** link from that same screen — it should already know which client/project you meant.
- Check the container vs. its children still read clearly.

## D. Review

- Set a deliverable to Ready for Review with a real review link. Does anything feel like it's guessing or hiding context you need?

## E. Delivery

- Mark something DONE for real. Does the project's health reflect reality afterward — no false "overdue" on work you actually finished?

## F. Operational truth

- Check Sensor Activity. If a session ran long or looks wrong, try correcting it right there and confirm you land back where you started, not somewhere else.
- Glance at Dashboard's totals after a correction — should update, not lag.

## G. Commercial truth

- Only look at real, existing evidence (Finance, contracts, billing). Don't create anything fake to test this.

## H. Booking / calendar

- If a real booking exists, check **Add to Google Calendar** on it.

## I. If something breaks

Don't stop to write a report. Just note, in one line each:

- **Time**
- **Page**
- **What I expected**
- **What happened**
- **What I was trying to do**

The most useful bug report today is: *"I was trying to finish a client job and the system made me stop."*
